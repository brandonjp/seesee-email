## Why SeeSee?

You run multiple apps — WordPress sites, Python services, Node.js APIs — each sending email through different providers. When something goes wrong, you're digging through provider dashboards, server logs, and inboxes.

**SeeSee gives you one place to see every email your apps sent.** Point your apps at SeeSee via REST API or SMTP, and every outgoing email gets logged, searchable, and browsable.

```bash
# One container. That's it.
docker run -d -p 8080:8080 -p 2525:2525 \
  -e SEESEE_ADMIN_PASSWORD=your-password \
  -v seesee-data:/data \
  ghcr.io/brandonjp/seesee-email:latest
```

## Features

<CardGrid>
  <Card title="REST API" icon="rocket">
    Log emails from any language with a simple POST request. Bearer token auth per app.
  </Card>
  <Card title="SMTP Ingest" icon="email">
    Point your app's SMTP settings at SeeSee. It captures every message, with optional relay to deliver them too.
  </Card>
  <Card title="Full-Text Search" icon="magnifier">
    SQLite FTS5 powers instant search across subjects, bodies, addresses, and error messages.
  </Card>
  <Card title="Multi-App" icon="list-format">
    Each app gets its own API key and SMTP credentials. Filter and search per app.
  </Card>
  <Card title="Web Dashboard" icon="laptop">
    Browse emails, view HTML previews, manage apps, and monitor stats — dark mode included.
  </Card>
  <Card title="Retention Policies" icon="setting">
    Automatic cleanup by count, age, or storage cap. Per-app overrides for fine-grained control.
  </Card>
  <Card title="Single Container" icon="seti:docker">
    SQLite database, no external dependencies. Deploy with Docker or Docker Compose in seconds.
  </Card>
  <Card title="Privacy First" icon="approve-check">
    Self-hosted — your email data never leaves your server. Configurable body storage modes for sensitive content.
  </Card>
</CardGrid>

       │                    │                    │
